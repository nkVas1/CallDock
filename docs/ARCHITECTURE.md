# Устройство CallDock

Документ для тех, кто меняет код. Как пользоваться программой — в [README](../README.md).

## Три процесса

```
┌──────────────── CallDock.exe (WPF) ────────────────┐      ┌──── Chrome ────────────────────────┐
│ окно · трей · горячие клавиши                       │      │ расширение (MV3)                    │
│ SessionController — источники записи                │◄─────┤ popup → service worker → offscreen  │
│ BrowserBridge — Kestrel на 127.0.0.1:47831          │ HTTP │ tabCapture + MediaRecorder (WebM)   │
│ ProcessingQueue — индекс вкладок, FLAC, расшифровка │      └────────────────────────────────────┘
│ UpdateService — Velopack, GitHub Releases           │
└───────────────┬─────────────────────────────────────┘
                │ запуск с аргументами, строки progress в stdout
                ▼
        CallDock.Worker.exe — Whisper.net (whisper.cpp)
```

- **CallDock.App** — интерфейс и вся запись. Один экземпляр на пользователя (мьютекс `Local\CallDock.Desktop`);
  повторный запуск просто выводит окно вперёд.
- **CallDock.Worker** — распознавание речи в отдельном процессе: сбой нативного кода не может уронить идущую запись.
  Приоритет процесса — ниже обычного.
- **CallDock.Core** — общее: модели данных, архив, захват звука, FFmpeg, модели распознавания.
- **extension/** — расширение Chrome для записи вкладок.

Сборка выпуска кладёт App и Worker в одну папку (оба self-contained, общая среда выполнения), рядом —
`tools/` с FFmpeg и `extension/`.

## Запись

`SessionController` запускает каждый выбранный источник как отдельную дорожку (`RecordingTrack`) и раз в три секунды
сохраняет `session.json`.

| Источник | Как пишется | Файлы дорожки |
|---|---|---|
| Микрофон, системный звук | WASAPI (NAudio), loopback для системного звука | WAV-сегменты по 5 минут → FLAC 24 бит |
| Звук приложения | WASAPI process loopback (Windows 10 build 20348+, на практике Windows 11) | то же |
| Экран, окно | ScreenRecorderLib, H.264 через Media Foundation | MP4 |
| Поток по ссылке | FFmpeg, копирование потоков без перекодирования | MKV |
| Вкладка Chrome | расширение, VP8 + Opus или только Opus | WebM |

**Звук пишется по времени, а не по пакетам.** `PcmTimelineWriter` ставит каждый пакет WASAPI на его место на шкале
сэмплов: пропуски становятся тишиной, наложения обрезаются. Поэтому дорожки разных устройств совпадают по времени, а
`OffsetSeconds` дорожки — момент её начала от начала записи.

**WAV во время записи, FLAC после.** WAV, оборванный сбоем, восстанавливается; оборванный FLAC — нет. После записи
`AudioCompactor` кодирует каждый сегмент во FLAC рядом с оригиналом, сверяет длительность и только потом удаляет WAV.

**Восстановление.** При запуске `Archive.Recover()` обходит папки архива: запись со статусом «идёт» помечается как
восстановленная после сбоя, её файлы остаются.

## Архив

```
Документы\CallDock\
  archive.sqlite3                       индекс: метаданные и полнотекстовый поиск (FTS5)
  2026\10\03-181605-0d8fc30b\
    session.json                        запись целиком: дорожки, расшифровка, метки, заметки
    tracks\<id дорожки>\00000.flac      сегменты дорожки
```

Источник истины — `session.json`; индекс можно удалить, он соберётся заново из папок. Изменения из разных мест
(окно, фоновая обработка) идут через `Archive.Update(id, change)`: прочитать, изменить, сохранить под общей блокировкой,
чтобы никто не затёр чужие поля.

## После записи

`ProcessingQueue` обрабатывает записи по одной и не начинает новую работу, пока идёт запись:

1. **Индекс вкладок** (`TabIndexer`). MediaRecorder пишет WebM без длительности и индекса перемотки. Файл копируется
   FFmpeg без перекодирования — с тем и другим. Здесь же видно, если звук вкладки короче видео (компьютер не успевал
   кодировать): у дорожки появляется предупреждение.
2. **Сжатие во FLAC** (если включено).
3. **Расшифровка.** Worker получает папку архива, id записи и файл настроек, режет звук на куски по 5 минут
   (whisper.net держит весь вход в памяти), пропускает тишину и печатает строки `progress <доля> <что сейчас>`.
   Результат — `transcript-result.json`, который приложение забирает в `session.json`.

Модели Whisper скачиваются с Hugging Face по закреплённому коммиту и сверяются по SHA-256 (`ModelManager`).
`ModelManager.Recommended` выбирает модель по числу логических процессоров.

## Мост для расширения

Kestrel слушает только `127.0.0.1:47831`. Каждый запрос проверяется трижды: заголовок `Host` — `127.0.0.1`; если есть
`Origin`, он должен быть ровно `chrome-extension://annnbeocomannganbpakmlleibjjkfie`; `Authorization: Bearer <код>` —
сравнение за постоянное время. Код подключения — 32 случайных байта в `%APPDATA%\CallDock\browser-token.txt`.

| Запрос | Что делает |
|---|---|
| `GET /health` | версия программы и идёт ли запись — для индикатора в расширении |
| `POST /tabs/start` `{title, video}` | новая дорожка в текущей записи или новая запись |
| `POST /tabs/{id}/chunk/{n}` | очередной кусок WebM; куски принимаются строго по порядку, повтор уже принятого игнорируется |
| `POST /tabs/{id}/ping` `{peak}` | уровень звука для индикатора; в ответе — не пора ли остановиться |
| `POST /tabs/{id}/finish` `{error}` | вкладка закончила; запись только из вкладок завершается с последней из них |

ID расширения фиксирован полем `key` в `manifest.json` (открытый ключ), поэтому одинаков на всех компьютерах и в любом
браузере на Chromium. Закрытый ключ не нужен: расширение не упаковывается в CRX.

**Расширение.** Popup — интерфейс. Service worker передаёт команды и управляет значком на панели. Offscreen-документ
держит `MediaRecorder` и `AudioContext`, пока popup закрыт и service worker спит: захватывает вкладку, режет запись на
секундные куски и отправляет их по порядку с повторами. Если кусок потерян окончательно, вкладка останавливается —
пропуск испортил бы файл.

## Обновления

Velopack: `Program.Main` первым делом вызывает `VelopackApp.Build().Run()` (обработка установки, обновления, удаления).
`UpdateService` смотрит выпуски `nkVas1/CallDock` на GitHub, скачивает пакет в фоне и предлагает перезапуск; во время
записи перезапуск откладывается, а при выходе обновление применяется само.

Установщик ставит программу в `%LOCALAPPDATA%\CallDock` и при удалении убирает эту папку целиком. Поэтому настройки
лежат отдельно, в `%APPDATA%\CallDock`, а записи — в документах.

## Ограничения, которые нельзя обойти

- WASAPI отдаёт уже декодированный звук: «исходное качество» — это PCM с устройства, а не сетевой кодек сервиса
  видеосвязи. Chrome тоже перекодирует вкладку.
- Несколько плееров внутри одной вкладки звучат одним потоком — разделить их нельзя. Каждый зал надо открыть в своей
  вкладке (в расширении есть поиск плееров на странице) или записывать по прямой ссылке на поток.
- Звук отдельного приложения недоступен в Windows 10 до build 20348.

## Проверка

- `dotnet test CallDock.slnx` — архив, хранение, разбор звука, фильтр «галлюцинаций» распознавания.
- `npm run test:browser` — четыре настоящие вкладки через настоящее окно расширения против запущенного CallDock:
  звук в каждой, корректное завершение, звук в сохранённых файлах до конца записи (`QA_TABS`, `QA_SECONDS`,
  `QA_QUALITY`).
- `CallDock.exe --verify-hardware <папка>` — запись звука одного процесса при параллельном звуке другого и запись окна;
  нужен Windows 11.
